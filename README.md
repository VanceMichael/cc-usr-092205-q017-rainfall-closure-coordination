# 持续降雨联合停课封路

协调持续强降雨下的停课、停运、封路与公众行动指引。

## 解决的问题

暴雨夜里家长先收到学校停课通知，几分钟后校车系统却仍提示正常发车——
气象、道路、教育部门各按不同落区更新信息。本项目把多方资料统一到同一份
预报格点上，并在对外发布前做联合一致性检查：

- **统一格点**：预报雨带、实况雨量、地质灾害点、积水道路、学校、校车线路、
  避险场所全部换算到格点；预警升级或雨带移动只影响真正相交的格点。
- **职责边界**：教育部门决定停课/复课，交通部门决定校车停运/恢复与封路/解封，
  应急部门统一发布，越权起草直接拒绝。
- **发布前拦截矛盾**：学校已停课而校车仍发车、线路途经封闭道路、封路与解封
  同时生效等情况，整批拦下，不让互相矛盾的决定先后到达公众。
- **原始时刻留痕**：跨午夜雨带用带日期的时刻表达；传感器离线、人工误报保留
  原始记录但不计入统计；撤销是补发新命令并指向原命令，原命令与时刻不删改。
- **按观测条件恢复**：复课、恢复发车、解封必须满足命令上写明的条件
  （近 1 小时雨量阈值、道路积水阈值、近 N 分钟有可用观测——离线期间不得判定恢复）。
- **同一版本多端一致**：每次发布生成只增版本，家长、司机、救援人员从同一快照
  取数；公众按当前位置只收到当前仍有效（未撤销、覆盖所在格点）的行动；
  历史版本快照可回放，不再靠后续短信猜测哪条通知有效。

## 资料约定

- `contracts/domain.schema.json`、`fixtures/domain.json`：领域概述资料。
- `contracts/scenario.schema.json`：完整指挥情景的字段结构。
- `fixtures/scenario.json`：虚构的跨区县暴雨夜样例（云溪区 × 临江县），
  含跨午夜雨带、雨带东移、离线传感器、人工误报、跨区封路与清晨按条件恢复。
- 全部样例不含真实个人信息，仓库不保存账号、密钥或连接串。

## 模块

- `src/geometry.py`：统一格点与落区相交
- `src/rainfall.py`：预警雨带、实况雨量、离线/误报质量标记与窗口统计
- `src/features.py`：地质灾害点、道路、学校、校车线路、避险场所、积水记录
- `src/orders.py`：部门命令、职责归属、撤销与恢复条件
- `src/coordination.py`：发布前矛盾检查、条件核验、版本快照与公众视图
- `src/scenario.py`：从情景 JSON 构建统一指挥世界

## 本地校验

```bash
python -m unittest discover -s tests
```

15 个测试覆盖：跨午夜雨带、雨带移动后仅相交格点变化、离线与误报留痕但排除、
跨区道路、越权拒绝、停课/发车矛盾拦截、线路途经封路拦截、观测条件不满足时
禁止恢复、撤销后原命令保留、三端同版本、按当前位置取数、历史快照回放。
